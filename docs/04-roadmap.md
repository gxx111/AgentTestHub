# 04 · 开发路线

> 版本：1.0  
> 更新：2026-10-17  
> 状态：有效  
> 负责人：研发负责人 / 产品

---

## 1. 愿景与阶段目标

**愿景**：成为企业 Agent 发布流程中的默认质量门禁——每次 Agent 版本变更，都先过 AgentTestHub。

**12 个月目标**：在"高风险业务 Agent 的发布前验证"这一细分品类中做到**最可信**，而不是功能最多。

**24 个月展望**：成为 Agent Reliability Engineering 的品类定义者之一，拥有场景市场、校准数据网络和标准话语权。

## 3. 季度计划

### 2026 Q4 · Phase 0：可信度修复

**主题**：先让"通过/失败"值得相信。

| 月 | 重点 | 可演示结果 |
|---|---|---|
| 10 月 | 清理、README、Issue 看板、确定性检查、LLM Judge 重写 | 同一用例的判决可追溯到 Span |
| 11 月 | 评分契约、安全否决、校准集、队列、Docker 沙盒起步 | Kappa 报告 + 可取消的实验 |
| 12 月 | Docker 沙盒完成、双控模拟器设计、场景包选型 | 2 个业务场景在容器中跑通 |

**KPI**：
- Judge 与人工一致性 Kappa ≥ 0.7。
- 已知坏用例 false pass < 5%。
- 确定性检查复现率 100%。
- 实验取消/超时可用。
- CI 覆盖 Python + Web + 黄金集。

**Gate 0**：未达标不进入 Phase 1；优先修评委，不新增功能。

---

### 2027 Q1 · Phase 1：仿真差异化

**主题**：从"聊天"到"业务世界"。

| 月 | 重点 | 可演示结果 |
|---|---|---|
| 1 月 | Docker 沙盒、Postgres 环境、快照/差分/负向断言 | 订单库被改错可被检出 |
| 2 月 | 双控用户模拟器、MCP 真实代理、故障注入 | 用户自己上传凭证/查状态 |
| 3 月 | 红队库、轨迹指标、2–3 场景包、设计伙伴 onboarding | 红队攻击成功/失败有证据 |

**KPI**：
- 3 个设计伙伴完成首次实验。
- 至少 1 个设计伙伴在真实 PR 使用门禁。
- 沙盒启动 p95 < 10s；100 用例 × 5 重复 < 30min。
- 场景包覆盖退款/审批/工单中至少 2 个。

**Gate 1**：没有 3 个活跃设计伙伴，不进入 Phase 2；先解决场景价值。

---

### 2027 Q2 · Phase 2：进入发布流程

**主题**：让评测成为 CI 的一部分。

| 月 | 重点 | 可演示结果 |
|---|---|---|
| 4 月 | Python SDK、pytest 插件、`ath` CLI | 本地一条命令跑场景 |
| 5 月 | GitHub Action、PR 评论、baseline 对比、报告 | PR 被门禁拦住并给出证据 |
| 6 月 | OTel 导出、3 框架适配、标注队列、校准仪表盘 | 外部 Agent Trace 可导入 |

**KPI**：
- 10 个团队（付费/试点）。
- 30% 实验由 CI 触发。
- 设计伙伴平均每周 ≥2 次实验。
- CI 门禁 p95 < 10 分钟（中小数据集）。

**Gate 2**：没有 CI 采用，不进入在线评估；先证明门禁价值。

---

### 2027 Q3 · Phase 3：生产闭环与企业化

**主题**：从发布前到生产中发现。

| 月 | 重点 | 可演示结果 |
|---|---|---|
| 7 月 | OTLP 摄入、Session/Thread 视图、在线采样 | 生产 Trace 自动评分 |
| 8 月 | 告警、漂移、Trace→标注→数据集 | 线上失败进入回归集 |
| 9 月 | Postgres/Redis/S3/队列规模化、SSO/RBAC/审计、Helm | 私有化一键部署 |

**KPI**：
- 在线评估覆盖 ≥1 个生产场景。
- 10 个付费团队；至少 3 个企业版。
- 通过外部安全评审/渗透测试。
- 数据隔离测试 100% 通过。

**Gate 3**：没有企业级安全/部署能力，不签大客户；先补齐治理。

---

### 2027 Q4 · 规模化与 24 个月展望

**主题**：品类与生态。

| 方向 | 目标 |
|---|---|
| 场景市场 | 20+ 可复用场景包；合作伙伴贡献 |
| 标准 | OTel GenAI Agent 约定、MCP 测试 profile、A2A 一致性 |
| 认证 | SOC2 Type I/II、ISO27001、等保 |
| 生态 | 5 个框架/云/SI 合作 |
| 研究 | 发布"评测的评测"年度报告；MAS 失败分类 |
| 国际化 | 英文文档、海外 region（按需求） |

**24 个月目标**：
- 成为"Agent 发布门禁"品类的默认候选之一。
- 100+ 付费团队；场景市场有网络效应。
- 校准数据/场景资产形成数据飞轮。

## 4. 发布列车

| 类型 | 频率 | 内容 | 受众 |
|---|---|---|---|
| 内部 nightly | 每日 | 主干构建、黄金集、E2E | 工程 |

### 4.1 版本策略

- `0.x`：beta，允许破坏性变更；每次变更写迁移说明。
- `1.0`：Phase 2 结束、API 稳定后发布。
- 语义化版本；企业版 LTS 分支。

## 5. 指标看板

### 5.1 北极星

### 5.2 质量

| 指标 | 定义 | 目标 |
|---|---|---|
| Judge Kappa | 与人工标签一致性 | ≥ 0.8 |

| 每团队周实验数 | ≥ 5 |
| CI 实验占比 | ≥ 30% |

| 指标 | 目标（12m） |

## 6. 决策门（Go / No-Go）

### Gate 0 · 可信度

- Kappa ≥ 0.7；false pass < 5%。
- 安全否决不可推翻。
- 无 P0 安全漏洞。
- **No-Go**：回到评委/评分，暂停新功能。

### Gate 1 · 场景价值

- 3 个设计伙伴每周使用。
- 至少 1 个真实回归被拦住。
- 场景包可复用（新客户 1 天内跑通）。
- **No-Go**：换场景/换客户，不扩功能。

### Gate 2 · 工作流

- 1 个生产 CI 门禁持续运行 4 周。
- CI 门禁误报率 < 5%。
- 开发者愿意在 PR 中使用。
- **No-Go**：优化 DX/稳定性，不做在线评估。

### Gate 3 · 企业化

- 通过安全评审。
- 私有化部署成功 2 家。
- SSO/RBAC/审计可用。
- **No-Go**：暂停大客户签约，补治理。

## 7. 招聘计划

| 时间 | 角色 | 原因 |
|---|---|---|
| 立即 | 评测科学家/工程师 | 校准、统计、实验设计是核心短板 |
| 立即 | 基础设施工程师 | 沙盒、队列、存储、K8s |
| Phase 2 | 解决方案工程师 | 设计伙伴交付、场景包 |
| Phase 2 | 安全工程师 | 沙盒隔离、合规、渗透 |
| Phase 3 | 客户成功/销售 | 企业扩张 |
| Phase 3 | 技术写作/开发者关系 | 文档、社区、标准 |

### 7.1 能力要求

- 评测科学家：LLM-as-judge 校准、统计、基准设计、论文/工程落地经验。
- 基础设施：Docker/K8s、Postgres、队列、可观测性、安全隔离。
- 解决方案：业务场景抽象、客户沟通、能把定制沉淀为模板。

---

## 8. 不做什么（12 个月内）

- 不做通用 LLM 可观测平台。
- 不做 Prompt 管理/Playground。
- 不做模型网关/推理服务。
- 不做 Agent 编排运行时。
- 不做公开榜单刷分。
- 不做泛行业"万能评测"。
- 不把多 Agent 作为唯一主线。
- 不为功能数量牺牲可信度。

---

## 9. 风险与路线调整

| 信号 | 调整 |
|---|---|
| 设计伙伴不买单 | 收缩场景，做更窄的"退款门禁"或"审批门禁" |
| 竞品免费提供仿真 | 加深垂直场景 + 私有化 + 校准数据 |
| Judge 成本过高 | 提高确定性比例，小模型初筛，按风险分层 |
| 企业销售周期长 | 先做团队版/自助版，积累案例 |
| 多 Agent 需求爆发 | 提前 Phase 3 的 MAS 模块，但不改主线 |
| 安全事件 | 暂停增长，做渗透/认证/客户沟通 |

## 10. 路线图维护

- 每月更新一次本文件；重大变更写 ADR。
- 每个 Gate 后做一次复盘：目标、结果、偏差、下一步。
- 路线图是承诺的**方向**，不是固定日期的功能清单；范围可调，质量门槛不可调。
