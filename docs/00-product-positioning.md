# 00 · 产品定位

> 版本：1.0

> 状态：有效

---

## 1. 一句话定位

**AgentTestHub 是企业 Agent 的发布门禁：用可复现的仿真环境、带证据的轨迹裁决和 CI 集成，在发布前回答"这个版本能不能上线"。**

品类名：**Agent Release Gate**（Agent 发布门禁），隶属 **Agent Reliability Engineering**（Agent 可靠性工程）。

我们不卖"又一个 LLM 评测平台"，也不卖"又一个可观测面板"。我们卖的是一个**发布决策**：每次改 Prompt、换模型、加工具、改权限，团队都能在合并/上线前拿到可审计的结论。

---

## 2. 问题

### 2.1 客户真实痛点

1. **改一个 Prompt 就可能坏掉另一条业务线**。Agent 的行为是概率性的、路径依赖的，传统单测覆盖不了工具调用、多轮对话和世界状态。
2. **评测结果是"感觉"**。很多团队仍在人工抽检、看几条 Trace、凭经验判断；没有基线、没有置信区间、没有可复现证据。
3. **评测与发布脱节**。评测在 notebook 里，发布在 CI 里；评测结果不能阻止一次坏版本上线。
4. **LLM-as-Judge 不可信**。没有人工校准、没有偏置审计、没有证据引用，评委分数无法用于合规或发布决策。
5. **真实环境难搭**。订单库、审批流、文件系统、MCP 工具、权限策略，远比聊天记录复杂；多数工具只评测文本。
6. **多 Agent 协作质量无人度量**。团队用了 LangGraph/CrewAI/AutoGen，但不知道是"配合得好"还是"互相推诿"。

### 2.2 为什么现在

- Agent 正从 Demo 走向生产，发布频率上升，回归成本变高。
- 模型、Prompt、工具、权限频繁变更，传统 QA 方法失效。
- OTel GenAI、MCP、A2A 等标准成熟，使"跨框架接入 + 真实工具环境"第一次可规模化。
- 企业需要可审计的 AI 质量证据，合规/风控开始介入 Agent 上线流程。
- 通用可观测平台已经商品化，但"业务世界仿真 + 发布证据"仍是空白。

---

## 3. 目标客户

### 3.1 ICP（理想客户画像）

- 中大型企业，已有 5–50 个生产或在研 Agent。
- 行业：电商/零售、金融、保险、电信、SaaS、企业 IT。
- 场景：客服、售后、订单、审批、工单、内部运维、销售助手。
- 组织：有独立 AI 平台团队或 QA/测试团队，已有 CI（GitHub/GitLab/Jenkins）。
- 约束：数据不能出院，要求私有化/混合云，关注合规与审计。

### 3.2 角色

| 角色 | 诉求 | 我们的价值 |
|---|---|---|
| AI 平台负责人 | 统一管理多团队 Agent 质量 | 标准化评测、发布门禁、资产复用 |
| QA / 测试负责人 | 用可自动化手段替代人工抽检 | 场景包、批量实验、CI 集成 |
| AI 工程师 | 快速定位失败原因 | Trace 证据、归因、修复建议 |
| 风控 / 合规 | 证明上线前做过安全与合规验证 | 审计报告、红队结果、签名证据包 |
| 工程效能 / DevOps | 把质量门禁接入现有流水线 | CLI、GitHub Action、Webhook |

### 3.3 购买触发点

- 一次由 Prompt/模型变更导致的线上事故之后。
- 一次合规评审要求提供"Agent 上线前测试证据"。
- Agent 从 1 个扩展到多团队、多版本，人工评测无法扩展。
- 准备把 Agent 卖给企业客户，需要质量证明。

---

## 4. 定位声明

> **面向**中大型企业里负责 Agent 上线的 AI 平台团队与测试团队，  
> **他们**每次改 Prompt、换模型、加工具都担心线上回归，却缺乏可复现、可审计、能进 CI 的评测手段，  
> **AgentTestHub** 是 **Agent 发布门禁**，  
> **它**用真实沙盒、双控用户模拟和带证据的轨迹裁决，在发布前回答"这个版本能不能上"，  
> **不同于**以可观测为中心的 LangSmith/Langfuse，也不同于代码框架 Inspect/DeepEval，  
> **我们**把业务世界状态、仿真交互、发布门禁和审计证据做成开箱即用的产品，并支持私有化部署。

### 4.1 价值主张

1. **少上线坏版本**：在 CI 中拦截回归，给出通过率、置信区间和失败证据。
2. **少花人工评测时间**：自动用户模拟、并行沙盒、可复用场景包。
3. **让评测结果可信**：确定性检查 + 校准过的评委 + Span 证据 + 可复现清单。
4. **让合规可审计**：签名报告、快照哈希、模型/Prompt/工具版本、红队结果。
5. **数据不出院**：私有化、BYOC、国产模型/信创适配。

## 5. 市场格局与竞争策略

### 5.1 市场分层

| 层 | 代表 | 他们占住的能力 | 我们的策略 |
|---|---|---|---|
| 通用可观测 + 评测 SaaS | LangSmith、Langfuse、Braintrust、Arize、W&B Weave、Galileo | Trace、数据集、实验、在线评估、标注、Prompt 管理 | 不正面竞争；通过 OTel 接入，做业务仿真与发布门禁 |
| 开源评测框架 | Inspect AI、Promptfoo、DeepEval、OpenAI Evals、RAGAS | 代码优先、CI、基准、红队 | 集成/导入；我们提供产品化工作流与企业治理 |
| 云厂商 | Azure AI Foundry、Vertex AI、Bedrock | 内置指标、OTel、持续评估、红队、云捆绑 | 跨云、本地、国产化、垂直深度 |
| 基准与仿真 | SWE-bench、Terminal-Bench、τ²-bench、OSWorld、WebArena | 任务、环境、公信力 | 借方法论；做私有、版本化、防污染的企业基准 |
| 标准/协议 | OTel GenAI、OpenInference、MCP、A2A | 互操作 | 原生支持，成为生态的一部分 |

### 5.2 竞争定位

| 对手 | 他们强 | 我们不打 | 我们打 |
|---|---|---|---|
| LangSmith / Langfuse / Braintrust / Arize | Trace、UI、生态、通用评估 | 通用可观测、Prompt CMS | 业务世界仿真、发布证据、私有化、垂直场景包 |
| Inspect / DeepEval / Promptfoo | 代码框架、基准、红队 | 纯框架灵活性 | 产品化工作流、协作、审计、企业治理 |
| Azure / Vertex | 云捆绑、内置指标、持续评估 | 公有云原生捆绑 | 跨云/本地/国产化、深度业务仿真 |
| 公开基准 | 公信力、任务库 | 刷榜 | 私有、版本化、防污染的企业基准 |

### 5.3 为什么是我们

- 已经跑通真实模型、沙盒、模拟用户、评委、实验统计、Trace 回放的闭环。
- 有真实的业务场景与状态断言，而不是纯文本评测。
- 团队具备全栈交付速度，能在数周内把评测工作流产品化。
- 中国私有化/合规市场是 US SaaS 的天然盲区。

## 6. 楔子与场景

### 6.1 首选楔子

**高风险、强流程、可验证**的业务场景：

1. **电商售后/退款**：订单状态、凭证核验、退款权限、提示注入。
2. **金融审批/SOP**：KYC、额度、风控、审批顺序、越权。
3. **内部工单/IT 运维**：权限、变更窗口、回滚、故障恢复。

共同点：有明确世界状态、有合规价值、失败代价高、可用确定性断言。

### 6.2 次选场景

- 多 Agent 研发团队（PM/架构/开发/测试）的协作质量。
- MCP 工具型 Agent 的权限与安全测试。
- 编码/终端 Agent（作为场景包，不作为主线）。

### 6.3 暂不主攻

- 通用聊天机器人评测（红海、低客单）。
- 公开榜单刷分（污染严重、无企业预算）。
- Prompt 管理与 Playground（免费附件）。
- 全栈 LLM 可观测（巨头 + OTel 商品化）。

---

## 7. 护城河

1. **场景/环境资产**：业务世界模型、状态断言、故障注入、双控用户剧本；越做越厚。
2. **校准与失败数据**：人工标签、Judge 校准集、flaky 历史、失败归因库；复利资产。
3. **工作流嵌入**：CI 门禁 + 生产 Trace 回流 + 发布审计；切换成本高。
4. **私有化与合规**：等保/信创/SOC2/数据不出域；企业入场券。
5. **开放标准与社区**：开源 SDK/Runner，贡献 OTel/MCP/A2A 规范；生态分发。

---

## 8. 商业模式

- **Open-core**：Runner、SDK、场景规范、CLI 开源（Apache 2.0）；企业版收 SSO/RBAC/审计/在线评估/私有市场/支持。
- **定价**：按席位 + 评测运行量/沙盒时长；私有化 license；场景包定制服务（逐步产品化）。
- **GTM**：
  - 3–5 个设计伙伴共创，换取真实数据与案例。
  - 发布"评测的评测"报告（Judge 与人工一致性、false pass/fail、flaky 率）建立信任。
  - 与 SI/云厂商合作交付私有化项目。
  - 开源核心获取开发者分发，企业版变现。

## 9. 成功指标

### 9.1 北极星指标

**每月被门禁保护的发布次数**（Release decisions gated per month）。

### 9.2 质量指标

- Judge 与人工标签的一致性：Cohen's Kappa ≥ 0.8。
- 已知坏用例的 false pass 率 < 5%。
- 同配置可复现率 ≥ 99%（确定性检查 100%）。
- Flaky 用例识别率 ≥ 90%。
- 从失败运行到根因定位 < 5 分钟。

### 9.3 采用指标

- 周活跃团队数、每团队周实验数。
- CI 触发实验占比 ≥ 30%。
- 生产 Trace 回流数据集占比。
- 设计伙伴转付费率。

---

## 10. 非目标

- 不做通用 LLM 可观测平台。
- 不做 Prompt 管理/Playground。
- 不做模型网关/推理服务。
- 不做 Agent 编排运行时（我们评测，不替代 LangGraph/CrewAI）。
- 不做公开榜单刷分。
- 不把多 Agent 作为唯一主线；它是差异化模块。

---

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 巨头把仿真/门禁做成免费功能 | 差异化被压缩 | 垂直场景深度 + 私有化 + 校准数据 + 生态 |
| Judge 不可信 | 产品价值崩塌 | 确定性优先、人工校准、公开"评测的评测"报告 |
| 评测成本高 | 客户不愿频繁跑 | 级联评委、缓存、采样、小模型、确定性检查 |
| 多 Agent 市场早期 | 投入回报低 | 作为模块，不做主线 |
| 企业定制拖成外包 | 毛利下降 | 场景包模板化、产品化交付 |
| 安全/合规事故 | 信任受损 | 沙盒隔离、出口控制、审计、渗透测试、认证 |
| 数据污染/刷榜 | 结论失真 | 私有基准、动态生成、holdout、版本化 |
