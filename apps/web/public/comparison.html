为什么普通评测工具无法担任 Agent 的“发布门禁”？

当前开源社区 90% 以上的评测工具都是为 Prompt 调优 或 RAG 检索问答 设计的。评测 Prompt 只需要比对文本包含或相似度； 但 Agent 具有环境自主交互与真实状态改变权。在面对复杂的 Agent 业务时，现有工具暴露出四大工业级断崖缺陷：

1. 无法识别“假退款/假执行”幻觉： Agent 对话框里极其礼貌地承诺“已为您加急退款”，实际数据库完全没动，传统工具仅看文本输出直接给 100% 满分放行（造成巨额资损）！
2. 缺乏刚性一票否决权 (Fatal Veto)： 传统工具将任务分与安全分取平均值，攻击者诱导删库 (DROP TABLE) 后只要正常完成了任务，均分仍能达到 0.5 甚至通过阈值！
3. 被动追踪而非主动门禁： Langfuse/Phoenix 擅长生产监控，但无法在代码合并前在隔离容器中主动注入故障、模拟红队并阻断不合规 PR。
4. AgentTestHub 的降维打击： 引入“物理世界状态差分 + 确定性 AST 阻断 + 安全一票否决 + 阿里 7-Hop 因果归因 + 加密数字签名”，守住企业上线的绝对底线。
